Record once. Replay with any AI agent.

Skill Recorder watches a tab, distils your clicks and fills into a clean SKILL.md, and hands it to Claude Code so the next run is fully autonomous — no rrweb-video gymnastics, no brittle xpath dumps.

$ browse run ~/.claude/skills/your-skill

From a single demo to a re-runnable skill

Three steps, all of them automatic. You stay in your browser; the file lands in your Downloads folder ready for Claude Code.

Step 1

Record

Start the side panel, do the flow once. We capture both an rrweb visual stream and a semantic action log — clicks, fills, navigates, key presses — with multi-strategy selectors and element fingerprints.

Step 2

Distill

The Save-as-Skill dialog strips recording noise (duplicate keys, redundant submit clicks, redirect chains), auto-parameterises every typed value, and flags clicks on dynamic-list items so an agent knows to re-pick.

Step 3

Export

One click produces a Claude Code skill: frontmatter, parameters, browse-CLI bash blocks per step, expectations, and an optional Precondition block that loads a pre-authed Browserbase context when login is needed.

What the agent actually receives

A live render of a real recording — fed through the same @skill-recorder/render function the extension uses. No screenshots, no faking: you'll see the exact markdown Claude Code reads.

~/.claude/skills/amazon-sg-search-and-add-to-cart/SKILL.md
---
name: amazon-sg-search-and-add-to-cart
description: Search a keyword on Amazon.sg and add the first result to cart.
allowed-tools: Bash
---

# Amazon.sg — search and add to cart

Search a keyword on Amazon.sg and add the first result to cart.

Domain: `www.amazon.sg`

## Parameters

Ask the user for any of these not already provided:

- `search_term` — Keyword to search for on Amazon.sg (example: `iphone`)

## Steps

### 1. Navigate to https://www.amazon.sg/

```bash
browse open https://www.amazon.sg/
```

**Expected:** "Search Amazon.sg" becomes interactable

### 2. Fill "Search Amazon.sg"

Target: role searchbox, aria-label "Search Amazon.sg", tag <input>
```bash
browse fill #twotabsearchtextbox '{{search_term}}'
```
Selector hints: `aria: searchbox:Search Amazon.sg`

**Expected:** URL becomes www.amazon.sg/s

### 3. Click the first product result

Target: text "First product in results", role link, tag <a>
> ⚠️ This appears to click a specific item from a dynamic list (e.g. a search result). The exact element will likely be missing when replayed with different parameters — re-snapshot the page and pick an appropriate item by relevance instead of trusting the recorded selector.

```bash
# Locate the element in the page.
browse snapshot
# Click using the ref from the snapshot output (look for the element matching:
#   selector: div.s-card-container a.a-link-normal.s-no-outline
# )
browse click <ref-from-snapshot>
```

**Expected:** A product detail page loads

### 4. Click Add to cart

Target: text "Add to cart", role button, aria-label "Add to cart", tag <input>
```bash
# Locate the element in the page.
browse snapshot
# Click using the ref from the snapshot output (look for the element matching:
#   selector: #add-to-cart-button
# )
browse click <ref-from-snapshot>
```
Selector hints: `aria: button:Add to cart`

## On failure

- If a `browse` command misses (selector resolves to nothing), run `browse snapshot` and re-locate the target by aria-label, role, or visible text.
- Each step lists multiple selector hints; try them in order. If none match, fall back to the **element fingerprint** in the step description and search the snapshot text.
- If the page state diverges from the `Expected` line, do not blindly continue — re-snapshot, understand the new state, and adapt.
- Steps marked with ⚠️ (dynamic list items) were recorded against a specific result. Choose an equivalent item from the current page rather than reproducing the recorded selector verbatim.

How it works under the hood

Side panel ↔ background service worker ↔ content script, with IndexedDB as the source of truth and a player page for rrweb-style visual review.
