16:T10f6,<h1 id="distilling-skills">Distilling skills</h1>
<p>Click <strong>Save as Skill</strong> in the side panel and the raw <code>ActionStep[]</code> becomes a list of editable <code>DraftStep</code>s. Each draft has an <code>action</code>, an <code>intent</code>, a <code>skipped</code> toggle, and (for fills) an <code>isParam</code>/<code>paramName</code> pair.</p>
<h2 id="default-skip-heuristics">Default-skip heuristics</h2>
<p>Real users always generate noise. The dialog removes the obvious noise by default — but every step is rendered and you can re-include it with one click.</p>
<p>| Pattern | Why we skip | |---|---| | <code>scroll</code> events | Almost never intentional in a click-flow | | <code>keyUp</code> events | Replay only needs <code>keyDown</code> | | Backspace / Delete keys | A subsequent <code>fill</code> overwrites the value anyway | | Duplicate consecutive same-key | User holding Enter | | <code>keyDown Enter</code> after a click on a text input with no <code>change</code> between | Pure recording artifact | | <code>click</code> on a submit-like button within 3 s of a <code>change</code> | <code>browse fill</code> already presses Enter — the submit click is redundant | | <code>navigate</code> within 5 s of a click / submit / change / Enter | Side-effect redirect chain, not a user action |</p>
<h2 id="parameter-detection">Parameter detection</h2>
<p>Every non-masked <code>fill</code> is auto-marked as a parameter. The param name is suggested from the input's <code>aria-label</code> or visible label (e.g. <code>Search Amazon.sg</code> → <code>search_amazonsg</code>). You can untoggle to keep the value literal, or rename the param. All params with the same name are deduped into one <code>SkillParameter</code>.</p>
<h2 id="the-dynamic-list-warning">The ⚠️ dynamic-list warning</h2>
<p>When a click's selectors look like a search-result or grid item (top selector contains <code>:nth-of-type</code>, or a known container class such as <code>s-card-container</code>, <code>puis-card</code>, <code>product-card</code>, <code>gridcell</code>), the renderer inserts a warning into the step body telling the AI agent to <strong>re-pick</strong> rather than reuse the recorded selector verbatim. This prevents the classic &quot;skill was recorded with the search term <em>X</em> but replayed with <em>Y</em>, so the literal product selector misses&quot; failure mode.</p>
<h2 id="auth-precondition">Auth precondition</h2>
<p>The dialog scans the recording for auth signals:</p>
<ul><li><code>change</code> step on a password input</li><li><code>navigate</code> to a known auth-provider host (<code>logto.app</code>, <code>auth0.com</code>, <code>accounts.google.com</code>, <code>appleid.apple.com</code>, <code>login.microsoftonline.com</code>, <code>okta.com</code>, <code>clerk.dev</code>, <code>firebaseapp.com</code>, …)</li><li><code>navigate</code> to an auth-style path (<code>/login</code>, <code>/signin</code>, <code>/oauth</code>, <code>/authorize</code>, <code>/register</code>, …)</li></ul>
<p>If any signal fires, the <strong>Requires authenticated session</strong> checkbox is auto-checked, and the rendered SKILL.md gets a <code>## Precondition</code> block telling the agent to load a pre-authed Browserbase context. You can also toggle the box manually for recordings where you were already logged in before recording started — the auto-detection can't see that.</p>
<h2 id="expectation-derivation">Expectation derivation</h2>
<p>For each kept step the distiller looks at the next step to derive an <code>Expected:</code> line:</p>
<ul><li>If the next step has a different URL → <code>URL becomes &lt;new-url&gt;</code></li><li>Else if the next step has a target selector → <code>&quot;&lt;target&gt;&quot; becomes interactable</code></li></ul>
<p>This becomes both the <code><strong>Expected:</strong></code> line under each step in the markdown <em>and</em> the verifier predicate used during in-extension replay.</p>
<h2 id="markdown-output-shape">Markdown output shape</h2>
<p>The <code>renderSkillAsMarkdown</code> function in <code>@skill-recorder/render</code> is pure: same <code>Skill</code> in, same string out.
